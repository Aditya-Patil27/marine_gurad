## AISStream persistence update — 7 November 2026

The bounded `POST /api/v1/sources/runs` AISStream operation now accepts
`persist_positions: true`, but the default remains metadata-only. Durable live
position writes require the separate local opt-in
`AISSTREAM_PERSIST_ENABLED=true`; it must remain false until User A confirms
the account's retention rights. When enabled, the route stores no more than 30
validated snapshot points, labels them `source_mode=live`, and keeps provider
reception/capture-time limitations. `source_runs` itself still stores only safe
run metadata, never positions, raw messages, or credentials. Docker was
unavailable when this change was made, so no live sample or container test is
claimed for this implementation.

## Local credentials

Add credentials to the existing, ignored `apps/api/.env` file. Docker Compose loads that file for the backend and worker. Leave values blank until registered; never commit the file or paste keys into chat.

- `AISSTREAM_API_KEY`: API key from [AISStream](https://aisstream.io/).
- `GFW_API_TOKEN`: personal API token from [Global Fishing Watch](https://globalfishingwatch.org/our-apis/tokens), not Global Forest Watch. A Forest Watch key will not authenticate to the fishing API.
- `COPERNICUS_MARINE_USERNAME` and `COPERNICUS_MARINE_PASSWORD`: Copernicus Marine account credentials from [Copernicus Marine](https://data.marine.copernicus.eu/register). These are distinct from the existing Copernicus client ID/secret fields.

The AIS snapshot and GFW identity search are connected. `GET /api/v1/sources/health` reports local source configuration, replay/SST freshness and the last persisted bounded provider run; it still makes no provider request, so `configured`/`not_checked` and last-run status are not current availability or coverage claims. `POST /api/v1/sources/runs` is the separate Analyst/Admin + CSRF route that performs one bounded AIS snapshot or historical GFW regional-event page and records safe metadata in `source_runs`. The Copernicus endpoint serves a prepared historical subset; automated refresh is not implemented. The local NetCDF and JSON are ignored by Git and are not included in a fresh checkout. To reproduce the subset, install `apps/api/requirements-copernicus.txt` in a separate environment, set the two Copernicus Marine credential environment variables, and run `python scripts/fetch_copernicus_sst.py` from `apps/api`. The script requests a size estimate, enforces a 10 MB limit on estimated file and transfer size, and refuses to overwrite either output. The downloaded and estimated sizes can differ. `scripts/prepare_copernicus_sst.py INPUT.nc OUTPUT.json` can separately convert the documented product and version. The endpoint expects `apps/api/data/copernicus/gulf_mannar_sst_20261018_20.json`. GFW results and quota headers are cached in backend process memory, so a restart clears them. The rolling request window and 429 cooldown are shared through the existing Redis service when available, with a process-local fallback; this is still best-effort and multiple processes may not share cached responses. Provider usage counters can lag 30 minutes; caching and pacing do not guarantee account-wide quota compliance. After changing credentials, recreate backend and worker containers to load updated environment values; an application reload alone does not update the container environment.

The GFW historical event adapter also exposes a map-ready bounded GeoJSON page at `/api/v1/gfw/events/regional/geojson`; it reuses the existing provider call and cache, preserves event dates and does not persist provider records. A 4 Nov 2026 local smoke query for Jan 2024 returned 5 features of 112 events. The frontend now has an opt-in historical layer and evidence download; browser verification is pending. Event locations are not vessel tracks.
