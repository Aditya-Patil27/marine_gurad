## Required behavior

1. `GET /api/v1/reports/` requires at least Viewer. Anonymous → 401.
2. `POST /api/v1/reports/` requires Analyst or Administrator plus valid `X-CSRF-Token` matching the CSRF cookie. Viewer, Approver-only → 403; anonymous → 401; missing/wrong CSRF → 403. Preserve existing request fields, optional SST behavior and report snapshot checksum.
3. `POST /api/v1/reports/{id}/sign` requires Approver or Administrator plus valid CSRF and `reviewed=true`. Analyst-only and Viewer → 403. The persisted `signed_by` is the current authenticated user's username. Keep accepting the existing `officer` field for frontend compatibility but do not trust it, and do not let its content determine identity; document the transition. Preserve 404, 409 for already signed/tampered snapshots, row locking and UTC sign time. No email/dispatch.
4. Specify dependency ordering so anonymous and insufficient-role responses are correct and no side effects occur on denied requests. Existing endpoint code called directly in tests must remain testable; adapt only affected tests.
5. Tell B exactly that existing report calls now require login/cookies and CSRF header; B owns frontend changes. Existing frontend cannot create/sign reports until B integrates auth. Other API routes remain unprotected.
