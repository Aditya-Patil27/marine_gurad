# A-003E — Truthful source provenance for vessel records and assessments

Status: COMPLETED — implemented and self-verified with focused checks on a disposable database. Owner: User A / implementation agent. Plan P1-A4/P2-A1. Completed 6 November 2026 under the autonomous implementation policy.

## Objective

Make persisted vessel records and their assessments carry truthful source provenance so local replay, synthetic demo data, caller-supplied ingest and provider-derived data cannot be presented as interchangeable or live. Missing provenance stays `unknown`; nothing is inferred as provider data.

## Delivered scope

1. Read the Postgres best-practices skill and confirmed the development migration head was `009`.
2. Added additive migration `010_vessel_provenance`:
   - `vessel_tracks.source` (`String(120)`, not null, default `unknown`).
   - `vessel_tracks.source_mode` (`String(20)`, not null, default `unknown`).
   - Check constraint `ck_vessel_tracks_source_mode` allowing `live`, `historical`, `replay`, `synthetic`, `unknown`.
   - Check constraint `ck_vessel_assessments_source_mode` allowing those plus `mixed`.
   - Existing rows were backfilled by the non-null defaults to `unknown`; no row was relabelled as real or provider-derived.
3. Labelled the write paths:
   - `scripts/seed_demo.py` writes `source='local demo seed'`, `source_mode='synthetic'`.
   - `POST /api/v1/ingest/ais` accepts optional batch-level `source` (≤120 chars) and `source_mode` (validated vocabulary); omitted values become `caller-supplied AIS ingest` / `unknown`. An invalid mode is rejected with 422 before any row is added.
   - `scripts/ingest_ais.py` labels future Marine Cadastre CSV imports `source='Marine Cadastre AIS CSV import'`, `source_mode='historical'`.
   - `VesselTrack` model defaults remain conservative (`unknown`).
4. Propagated provenance through reads:
   - `risk_engine.Ping` and `fleet.load_pings` now carry `source`/`source_mode`.
   - `GET /vessels/`, `GET /vessels/{mmsi}` (summary and each track point) expose the stored values; legacy callers without provenance return `None` rather than an invented mode.
   - The vessel map layer selects and returns `source`/`source_mode`.
   - `GET /sources/health` local-vessel block reports the actual `source_mode` (`unknown`, one mode, or `mixed`) and the distinct `source_modes` list.
5. Assessment provenance:
   - `assessments.derive_source_mode(pings)` returns the single recorded mode, `unknown` when nothing was recorded, or `mixed` when a vessel window disagrees.
   - `POST /alerts/assessments/sync` uses that mode for the stable `(mmsi, rule_version, source_mode)` ID and persisted row instead of a constant.
   - `GET /alerts/assessments` reports the page mode as the single mode or `mixed`; the limitation text now explains derivation and unknown/mixed rather than claiming universal unknown.
6. Updated the data API contract, data manifest, README, progress, plan, backlog and this record.
