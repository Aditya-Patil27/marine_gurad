# A-006C — Shared GFW provider pacing with a safe local fallback

Status: COMPLETED — implemented and self-verified with focused tests and a live local Redis smoke. Owner: User A / implementation agent. Plan P3-A1/A5. Completed 6 November 2026 under the autonomous implementation policy.

## Objective

Make Global Fishing Watch rate-limit pacing and cooldown state shared across backend and worker processes using the existing Redis service, while preserving a safe process-local fallback when Redis is unavailable. This is an operational reliability slice, not a claim of provider availability, quota compliance or continuous jobs.

## Delivered scope

1. Added `app/services/provider_pacing.py` (`GfwPacer`):
   - Namespaced Redis keys for the rolling 60-second window, 429 cooldown and last observed rate headers.
   - Short connect/socket timeouts and bounded key TTLs.
   - Process-local fallback on any Redis error, with a 30-second retry suspension.
   - Status fields for last transport (`redis`/`local`), shared state, degraded state, Redis configuration and window limits.
   - No Redis URL, password or provider token in status/serialized output.
2. Integrated the pacer into `app/api/gfw.py`:
   - Shared cooldown and rolling window checks before provider attempts.
   - One pacing acquisition per actual attempt, with the existing per-process one-second spacing and local 60/minute guard retained.
   - 429 cooldowns persisted to the shared window.
   - Observed rate headers stored for cross-process reuse.
   - `provider_health()` now exposes a nested `pacing` object and keeps existing status fields compatible.
3. Added `tests/test_provider_pacing.py` with a deterministic in-memory Redis fake:
   - window limit and expiry, cooldown blocking, Redis-error local fallback, rate snapshot round-trip, status/secret checks and a GFW call refusing a second request when the window is full;
   - a failure-suspension check proving an already-created client is not retried for 30 seconds and recovers afterwards.
4. Updated the source-health contract, data manifest and README wording.
