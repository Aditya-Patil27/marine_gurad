## Outcome

Allow an analyst to create a hashed report and reviewed case from one re-fetched historical GFW event when no AIS observation or vessel assessment exists. The record must say that AIS/assessment evidence is unavailable; a GFW event is not a vessel track, live position, fishing proof or illegality proof. Existing assessment-backed report/case behavior remains compatible.

## Result

**Outcome.** COMPLETED. `POST /reports/` accepts an explicit `event_only: true` basis that re-fetches the bounded GFW page, verifies the event ID and `vessel.ssvid == mmsi`, and hashes a snapshot with `evidence_basis: "gfw_event_only"`, `ais_evidence.status: "unavailable"`, `assessment.status: "unavailable"`, the canonical `gfw_event_evidence` (`snapshot`, `sha256`, `integrity_note`) and explicit limitations. It never calls `get_vessel`, requires or synthesizes an assessment, copies a risk score or labels the event as AIS. Optional ocean context remains independently dated. `POST /cases/` accepts exactly one basis: `assessment_id` (unchanged path) or `report_id` for an event-only report. The report basis verifies report integrity, the event-only snapshot marker, the embedded canonical GFW hash and the event MMSI before insert, then creates the null-assessment case, `opened` event and revision 1 in one short transaction (`version: 1`). Later revisions on a null-assessment case run the same verification; assessment-backed cases keep the assessment-ID check. Auth, CSRF, expected-version, status and integrity checks are unchanged.
