## Implementation result — OpenCode

Status: **IMPLEMENTED** (4 November 2026), awaiting Codex review. A prior partial attempt was superseded and fully rewritten; all listed paths below reflect the current implementation.

### Behaviour

- Additive migration `006_auth_tables` adds `users`, `user_role_assignments` and `user_sessions`. No existing evidence table is altered. Username is normalized to lowercase with a unique constraint; email is optional and unique; sessions store only a SHA-256 token digest; role rows carry grant/revoke metadata; timestamps are UTC (`timestamptz`).
- Passwords use Argon2id via maintained `argon2-cffi==23.1.0` (added to `apps/api/requirements.txt`). Unknown-user and wrong-password logins both perform a verification and return the same generic `401`.
- `POST /api/v1/auth/login` sets an HttpOnly `samudra_session` cookie and a readable `samudra_csrf` cookie (`SameSite=Lax`, `Secure` controlled by `AUTH_COOKIE_SECURE`). One active session per user; a new login revokes earlier sessions. Default TTL 480 minutes.
- `POST /api/v1/auth/logout` requires the session cookie and `X-CSRF-Token` equal to the CSRF cookie (double-submit); it revokes the session and clears both cookies.
- `GET /api/v1/auth/me` resolves identity only from the session cookie; it returns `401` for missing, revoked, expired or disabled-account sessions.
- Bounded, process-local failed-login throttle returns `429` with `Retry-After`; the store evicts least-recently-touched keys and is documented as per-process only.
- Exported dependencies: `get_current_user`, `require_roles(*roles)`, `require_viewer`, `require_analyst`, `require_approver`, `require_admin`, plus `csrf_protect`. Administrator implies all other roles. None are applied to legacy routes in this task.
- `scripts/create_local_admin.py` is interactive, uses hidden password input, has no default credentials, no password command argument, checks for an existing username before prompting for a password, and exits `1` on duplicate.

### Decisions and dependencies

- Maintained Argon2id (`argon2-cffi==23.1.0`) instead of custom hashing; opaque tokens from `secrets.token_urlsafe(32)`; stored as SHA-256 digests.
- Cookie-only transport for A-001 (no bearer/API-token mechanism yet); CSRF by double-submit cookie; no cross-site browser support.
- Administrator implies every role; documented in `docs/contracts/AUTH_API.md`.
- Login throttling is bounded in-process, not shared across workers; documented as a workstation defence.
- Existing `SECRET_KEY`/`JWT_SECRET` settings are untouched and unused by this flow.
