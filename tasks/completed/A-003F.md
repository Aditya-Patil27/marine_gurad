# A-003F — Stable, deduplicated legacy alert projection

Status: COMPLETED — implemented and self-verified with focused tests and a local read smoke. Owner: User A / implementation agent. Plan P1-A4/P2-A1. Completed 6 November 2026 under the autonomous implementation policy.

## Objective

Make the existing `GET /api/v1/alerts/` projection stable and deduplicated without claiming persistent alert lifecycle. Repeated reads of the same vessel/zone condition return the same alert ID and observation time, duplicate generator rows collapse, and provenance is explicit.

## Delivered scope

1. Kept the existing public response shape (`id`, `type`, `severity`, `title`, `description`, `timestamp`, `location`, `metadata`) and severity filter/sort/limit behavior.
2. Added deterministic `alert_identity()` and `alert_id()` helpers: UUIDv5 over `(type, mmsi, mpa_id or mpa_name)`.
3. Deduplicated generator rows by that identity before mapping, keeping the highest severity/risk entry deterministically.
4. `timestamp` now uses the latest stored vessel position time from the generator join; request time is only a fallback when the generator supplies none.
5. `alert_generator` now selects the latest `timestamp`, `source` and `source_mode` alongside the existing latest-position fields, so alerts carry truthful track provenance.
6. `metadata` explicitly adds `source`, `source_mode`, `persisted: false` and `lifecycle: "ephemeral_projection"`.
7. Added focused no-network tests and updated the data API contract and README.

## Files

- `apps/api/app/api/alerts.py` — deterministic identity, deduplication, stable timestamp, provenance metadata.

No migration, schema change, provider endpoint, threshold, route predictor, auth, ingest, frontend/B-owned file, dataset or credential value was changed.

## Data and provenance

No acquisition. Alerts remain a derived, ephemeral screening projection and are not evidence of illegal activity. IDs are stable for the same condition, but nothing is persisted or acknowledged. `source`/`source_mode` come from the latest track row and can be `unknown`/`mixed` at the fleet level; this slice does not upgrade them.
