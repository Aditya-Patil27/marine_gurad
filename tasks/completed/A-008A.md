# A-008A - Read-only investigation triage

Status: COMPLETED. Owner: User A. Plan P3-A3. No provider or migration dependency.

## Objective

Expose one authenticated, paginated backend view that combines the latest
persisted assessment with persisted alert and case counts. It must support a
reviewer prioritizing work without turning screening data into a legal finding.

## Required scope

- Add a Viewer-or-higher `GET /api/v1/triage/assessments` endpoint.
- Return bounded pagination and optional MMSI filter.
- For every persisted assessment, include score, level, provenance, current
  open/acknowledged/resolved alert counts, open/closed case counts, and a
  deterministic review state: `under_review`, `needs_review`, or `monitor`.
- An open case takes precedence. Otherwise a HIGH alert or HIGH assessment
  level needs review. All remaining rows monitor.
- Return an explicit weather status `not_checked`; this endpoint must not call
  a weather provider and weather failure must never reduce scores or states.
- Add focused helper/route authorization tests and document the API contract.

## Boundaries

Read-only only. No schema changes, provider calls, alert/case mutation,
frontend edits, risk-score changes, or claims that triage proves illegal
activity.
