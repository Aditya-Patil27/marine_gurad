# A-006A — Read-only source health contract

Status: COMPLETED — focused local verification complete. Owner: User A / implementation agent. Plan P3-A1/A5. First bounded slice of A-006 after A-005; not the whole provider-job task.

## Objective and context

Expose one read-only `GET /api/v1/sources/health` response that tells an operator what each configured source can and cannot claim right now, without making external calls and without exposing credentials. The judging runbook explains failures manually; this endpoint gives the same facts machine-readably for the console and future operator checks.

Current state: GFW has `/gfw/status` (configured flag, in-memory quota headers), Copernicus/SST loading lives in `app/api/ocean.py`, AISStream configuration and `settings` are available, and local vessel records have no verified provider provenance. There is no combined health view. Incremental provider jobs, shared cross-process pacing/checkpoints and a real AIS sample remain out of scope for this slice.

## Data and dependencies

No acquisition. The endpoint reads only local state: `vessel_tracks`, the prepared Copernicus JSON artifact, in-memory GFW status and `settings` booleans. Do not turn `configured` into `available`; provider availability is `not_checked` because this endpoint makes no network request. Never return a key/token/password or a connection string.

## Implementation steps

1. Add `sources.py` with pure helpers for replay freshness, prepared-SST status and AIS/Open-Meteo status, plus a combined `build_source_health(db, now)`.
2. Add a reusable `provider_health()` in `gfw.py` and use it from both `/gfw/status` and the new endpoint, preserving the existing response fields.
3. Register the router in `main.py`; keep all existing contracts unchanged.
4. Add focused tests for fresh/stale/empty replay, available/missing SST, unconfigured GFW/AISStream and no-network/no-secret behavior.
5. Document the contract and update the task/progress status.

## Acceptance criteria

- `GET /api/v1/sources/health` returns `checked_at` (UTC), per-source `status`, and explicit limitations; local replay reports count/vessels/latest/freshness; SST reports historical mode and dataset on success and `unavailable` on missing artifact; GFW/AISStream say `configured` or `not_configured` and availability `not_checked`; no secret value appears.
- No external HTTP request, DB write, migration, seed or B-owned edit.
- Focused tests pass and the live endpoint is smoke-checked without breaking `/gfw/status`.
- Invalid/absent data returns a visible status, not a fabricated success. No public-security claim is made.
