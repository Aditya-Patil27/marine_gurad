## Implementation result — Antigravity

### Implementation Details
- **Updated `apps/api/app/api/vessels.py`**:
  - Implemented `get_vessel_limitations()` which returns a freshly instantiated list of `{key, label, detail}` objects compatible with User B's `DataLimitations` component in `apps/web/src/pages/Cases.jsx`:
    1. `source_mode`: Records that track records do not reliably log source, mode, or receiver coverage; shore/satellite reception gaps are unknown and not assumed complete.
    2. `indicators_not_proof`: Clarifies that AIS gaps, loitering, and encounters are investigative indicators, not proof of intent, transshipment, or an offence.
    3. `boundaries`: States that demo marine protected area boundaries are indicative; gazetted limits and rules must be separately verified.
    4. `heuristic_score`: Explains that the rule score is an explainable heuristic, not a validated probability or legal determination.
  - Added `"limitations": get_vessel_limitations()` to `get_vessel("/{mmsi}")` response dictionary. Each call creates a fresh list instance, preventing shared mutation.
  - Scores, factors, checks, timestamps, and track pings are completely preserved.
- **Report Snapshot & Checksum Integration**:
  - `create_report` in `apps/api/app/api/reports.py` invokes `get_vessel(request.mmsi, 24, db)` to populate `snapshot` before calling `digest(snapshot)`.
  - As a result, newly created report snapshots capture `limitations` automatically under the SHA-256 digest without requiring changes to `reports.py`.
  - Modifying or removing any limitation in the snapshot invalidates the checksum. Old stored reports in the database remain untouched.
- **Tests Added (`apps/api/tests/test_vessel_limitations.py`)**:
  - `test_vessel_limitations_returns_new_list_matching_b_shape`: Verifies distinct list instances, required keys (`key`, `label`, `detail`), and non-empty strings.
  - `test_get_vessel_includes_limitations_in_detail_response`: Verifies `get_vessel` includes the 4 limitations objects in its output.
  - `test_new_report_captures_limitations_in_hashed_snapshot`: Verifies that `create_report` binds limitations into the snapshot and SHA-256 digest, and altering/removing a limitation invalidates `integrity_ok`.
- **Documentation Updated (`docs/contracts/USER_A_DATA_API.md`)**:
  - Documented `GET /vessels/{mmsi}` `limitations` array structure and uncertainty scope.
  - Documented that report snapshots capture `limitations` before calculating the SHA-256 digest.
  - Noted that User B's branch `origin/b/sprint` remains unmerged and report UI requires login/CSRF integration.
