# A-003G — Persistent alert storage and lifecycle

Status: COMPLETED — implemented and self-verified with focused unit/integration checks, a disposable migrated database and live authorization smokes. Owner: User A / implementation agent. Plan P1-A4/P2-A1. Completed 6 November 2026 under the autonomous implementation policy.

## Objective

Persist derived alert conditions with an auditable lifecycle so reviewed alerts keep status and history across reads, reusing the stable A-003F identity and leaving the legacy `/alerts/` projection unchanged.

## Delivered scope

1. Read the Postgres best-practices skill and confirmed the development migration head was `010`.
2. Added additive migration `011_alert_lifecycle`:
   - `alert_records` with the deterministic UUID primary key, unique `(type, mmsi, zone_key)` identity, normalized `HIGH`/`MEDIUM`/`LOW` severity, observation window, optional paired location, metadata JSONB, track `source`/`source_mode`, `open`/`acknowledged`/`resolved` status, acknowledgement/resolution fields, optimistic `version`, and UTC created/updated times.
   - `alert_events` append-only log (`created`, `observed`, `acknowledged`, `resolved`, `reopened`) with actor, optional note and timestamp, cascading on record deletion.
   - Constraints for status/severity/source-mode vocabulary, version, observation order, location pairing/bounds, acknowledgement/resolution consistency and non-empty identity fields.
   - Unique identity index plus `(status, last_observed_at DESC)` and `(mmsi, last_observed_at DESC)` read indexes.
3. Added `app/api/alert_records.py` and mounted it under the existing `/alerts` prefix:
   - `POST /alerts/sync` (Analyst/Admin + CSRF) runs the generator once, deduplicates with the A-003F helpers, inserts new identities as `open`, refreshes open/acknowledged observations without losing status, leaves resolved records untouched and reports them as `skipped_resolved`, and never moves `last_observed_at` backwards.
   - `GET /alerts/stored` (Viewer+) supports bounded pagination plus `status`, `severity` and `mmsi` filters with validated vocabulary.
   - `GET /alerts/stored/{id}` (Viewer+) returns the record plus its event history.
   - `POST /alerts/stored/{id}/acknowledge|resolve|reopen` (Analyst/Admin + CSRF) require `expected_version`, reject stale versions/invalid transitions with 409, and append an event with the session username.
4. Refactored the A-003F projection helpers into reusable severity/title/description/context/location/dedup functions so stored titles and descriptions match the live projection; `GET /alerts/` behavior and shape are unchanged.
5. Kept the legacy `/alerts/` contract and B-owned frontend untouched; stored lifecycle is additive and not yet rendered by B.
6. Added focused no-network unit checks and disposable-database integration checks, plus a disposable runner.
