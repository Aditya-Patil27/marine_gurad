# A-006B — Persistent provider-run checkpoints and source health integration

Status: COMPLETED — implemented and self-verified with focused checks on a disposable database. Owner: User A / implementation agent. Plan P3-A1/A5. Completed 6 November 2026 under the autonomous implementation policy; no separate review gate.

## Objective

Turn the source-health snapshot into a usable operational slice: persist bounded provider-run outcomes and checkpoints for AISStream/GFW jobs, expose them through source health, and add a manual authenticated trigger for a bounded run. This is not a claim of continuous live coverage or successful real AIS ingestion.

## Delivered scope

1. Read the Postgres best-practices skill and A-006A brief before schema work; confirmed development head `008`.
2. Added additive migration `009_source_runs` with a `source_runs` table:
   - `bigint generated always as identity` primary key, UTC `timestamptz` start/finish, provider/operation/status/mode, bounded request/position/event counts, safe error category/message, JSONB checkpoint and `triggered_by`.
   - Check constraints for provider/operation/mode pairing, status, error consistency, count shape and time order.
   - Composite index `ix_source_runs_provider_started_at (provider, started_at DESC)` for the last-run access path.
   - No credentials, raw provider payloads, positions or event records are stored in this table.
3. Added `app/services/source_runs.py` with bounded message sanitization, error categorization, insert and `DISTINCT ON` latest-run reads.
4. Refactored the adapters without changing their read contracts:
   - `aisstream.collect_snapshot(max_positions, duration_seconds, use_cache)` and bound query parameters on the existing snapshot route.
   - `gfw.fetch_regional_events(start_date, end_date, offset, limit, use_cache)` shared by the existing regional-events route and the manual run; tracks/SAR paths are untouched.
5. Added protected `POST /api/v1/sources/runs`:
   - Analyst session required (Administrator implies Analyst), then CSRF, before business logic.
   - Discriminated request: AISStream (`max_positions` 1–30, `duration_seconds` 1–12) or GFW historical regional events (`start_date`/`end_date`, `offset` 0–10000, `limit` 1–50, manual window 1–31 days).
   - AIS manual runs disable cache reuse; an empty sample records `empty`, never coverage.
   - GFW provider failures return HTTP 200 with `unavailable`/`failed` and a persisted record; an out-of-window GFW request is persisted as `rejected` and returns 422 before any provider call.
   - `request_count` counts bounded operations issued; provider-internal retries are not counted separately.
6. Extended `GET /api/v1/sources/health` with `last_run` and `last_run_note` for AISStream and GFW while preserving `external_calls: false`, `writes: false` and `availability: not_checked`. Last-run status is explicitly historical metadata, not current availability.
7. Updated the source-health contract, data manifest, README, progress and roadmap.
