# A-004E — Bind real GFW event evidence to the reviewed export

Status: READY FOR A / OpenCode. Owner: A (`apps/api/**`, contracts and data manifest). B continues B-005 separately.

## Outcome

An authenticated analyst can select one historical GFW event from the existing bounded regional query and persist a canonical, checksummed source-evidence snapshot that can be attached to the existing report/case revision path. The snapshot may include the independently dated Copernicus SST context with its existing non-association statement. It must remain a historical inferred event point, never a vessel track or proof of illegality.

## Smallest complete implementation

- Reuse the current GFW event lookup/evidence canonicalization, report hash, assessment identity and case revision integrity checks. Do not create a parallel report system or new provider adapter.
- Add only the persistence/contract needed to bind the selected provider event ID, requested date window, retrieved source metadata, original event dates/position, limitations and optional SST context to a report snapshot and case revision.
- Keep provider retrieval bounded. A failed lookup, missing event, changed page, unavailable SST or mismatched vessel/assessment must fail visibly and must not create a partially linked report/case record.
- Preserve independent timestamps. Do not imply that SST is concurrent with the event, convert an event point into AIS positions, or transfer replay risk claims to the real event.
- Require the existing Analyst/session/CSRF boundary for mutation. Use an additive, legacy-safe migration only if durable source evidence cannot fit an existing appropriate record.

- Negative checks for missing/changed event evidence and unavailable optional SST; no partial report/case linkage.
- Existing report creation without source evidence stays compatible.
