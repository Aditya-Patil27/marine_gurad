## Smallest complete caller

- When a selected GFW event is present and the vessel request returns 404, keep the existing missing-AIS message and show one explicit action such as `Create event-only review`. Do not offer it for a generic API failure or without a selected event.
- Send `POST /reports/` with `mmsi`, `event_only: true`, the exact `gfw_event_id`, dates, offset and limit carried from the map, plus the existing optional GFW ocean-context flag. Do not send assessment ID, replay window, lookback, weather context or invented vessel fields.
- On report success, send `POST /cases/` with only `{report_id, title}`. A-004F creates revision 1 atomically, so do not call assessment sync or `POST /cases/{id}/revisions` for this path. Navigate to the returned case and make its stored GFW evidence/export reachable through the existing screens.
- Retain the report ID if case creation fails so an explicit retry does not create another report. Disable the action while requests are in flight. Do not automatically retry an ambiguous failed case request; show the server/network error and tell the analyst to reload/check Cases before retrying. Existing assessment-backed case creation and 409 recovery stay unchanged.
- Display the event-only snapshot's unavailable AIS/assessment state and limitations using the existing report evidence UI. Do not show a risk score, track link or assessment claim when those fields are absent.
